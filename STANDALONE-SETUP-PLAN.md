# STANDALONE-SETUP-PLAN — agent-router backbone

## 1. Repo contents vs owner-specific

**Commit to the repo (no keys, no values, no personal paths):**
- `backbone/` package — router, KeyPool, workers, NIM client, bandit, enforcement hook
- `config/backbone.yaml` — base template; `nim.keys` is names only (`[NIM_1, NIM_2, NIM_3, NIM_4, NIM_5]`)
- `config/routes.yaml`, `config/providers.yaml`
- `requirements.txt`, `Makefile`, `tests/`, `docs/`, `eval/`, `scripts/`
- `.gitignore`: `data/`, `.venv/`, `*.env`, `*.bak`, `secrets/`, `__pycache__/`

**Owner-specific, never committed (machine-local):**
- `~/.agent-router/backbone.yaml` — generated by `backbone init`
- `~/.agent-router/projects.yaml`, `~/.agent-router/data/` (SQLite DBs, `key_state.json`, `doctor.json`)
- `~/.env` or `~/.config/agent-router/env` — NIM_1..NIM_5 **values**
- `~/.ssh/config` hosts; agent CLIs on PATH (pi, claude, codex, opencode, jcode, agy)

Rule: repo holds env-var names only; values and absolute owner paths stay out of the repo. Committed config uses `~` expansion only.

## 2. Clone + create user config (`~/.agent-router/backbone.yaml`)

```bash
git clone https://github.com/<owner>/agent-router.git
cd agent-router
python3.13 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Owner creates `~/.env` (out of band, never committed):
```
NIM_1=<value>
NIM_2=<value>
NIM_3=<value>
NIM_4=<value>
NIM_5=<value>
```

```bash
.venv/bin/python -m backbone discover   # inventories agents + key NAMES (values never read)
.venv/bin/python -m backbone init       # writes ~/.agent-router/backbone.yaml (non-destructive)
```

`init` derives config from discovery: `nim.keys` = discovered NIM names, `default_key` = first name, `workers` = only detected binaries, `escalation.expert` = first of codex/claude found. Review `~/.agent-router/backbone.yaml` before running jobs; set `nim.keys: [NIM_1, NIM_2, NIM_3, NIM_4, NIM_5]` if needed. Keys are read by `keys.load_named()` from env files + process env (first file wins) — no wrapper script required; `make keys/run` optionally use `~/.claude/scripts/with-env`.

## 3. Verify all 5 NIM keys (NIM_1..NIM_5) in the KeyPool

```bash
.venv/bin/python -m backbone keys
```
Expected: pool status lists NIM_1..NIM_5, `present: true` for all, `cooling_s: 0`, `in_window: 0`. Values never printed.

Programmatic check:
```bash
.venv/bin/python - <<'EOF'
from backbone.keys import KeyPool, with_discovered
names = with_discovered(["NIM_1","NIM_2","NIM_3","NIM_4","NIM_5"], pattern=r"NIM_\d+")
assert names == ["NIM_1","NIM_2","NIM_3","NIM_4","NIM_5"], names
pool = KeyPool(names)
assert set(pool.names) == {"NIM_1","NIM_2","NIM_3","NIM_4","NIM_5"}, pool.names
st = pool.status()
assert all(v["present"] for v in st.values()), st
print("5 NIM keys present in pool")
EOF
```

Also confirm `backbone discover` shows `providers.nim` base URL and `~/.agent-router/backbone.yaml` has `nim.keys: [NIM_1..NIM_5]`. Usability = present in env; real-call verification is section 5 (optional spend, gate `noop`).

## 4. Agent clients hook into the router — no internal subagents

- Every worker adapter (`PiWorker`, `ClaudeWorker`, `CodexWorker`, `JcodeWorker`, `OpencodeWorker`, `AgyWorker`, `GooseWorker`, `GenericWorker`) receives one shared `KeyPool` from `Backbone` core. NIM calls go through `pool.call()` / `nim.chat(pool, ...)` with failover across NIM_1..NIM_5 (retry, cooldown, rpm cap).
- Router entry points: `backbone run`, `fanout`, `swarm`, `delegate`, `submit`/`daemon`, `serve` (loopback HTTP API on 8799), MCP. External agents address the router via `backbone serve` `/submit`; nodes connect outbound only through `ssh -L` tunnel. No agent calls NIM directly.
- Invariant: workers are bounded harness processes; they never spawn sub-agents. `delegate` uses the router's own split→fanout→integrate, not Claude Code's internal subagents (avoids too-many-requests).
- Enforcement hook (`backbone/hook.py`) installed in `~/.claude/settings.json` redirects Agent|Task once to the router; shadow-only, fail-open.
- Config guardrails: `decide.allow_experts: false`, `delegate.heavy: false` (opt-in); workers come from discovery only.

## 5. Verification/test procedure

```bash
make install          # venv + pip install -r requirements.txt
make discover         # inventory agents, keys, ssh hosts, projects
make init             # write ~/.agent-router/backbone.yaml; review it
make keys             # pool status: NIM_1..NIM_5 present
make doctor           # read-only probe of every detected worker (data/doctor.json)
make test             # .venv/bin/python -m pytest tests -q
make run prompt="..." worker=nim1 gate="noop"   # one gated NIM run (spends quota)
```

Key checks:
- `backbone keys` → all 5 present, no values printed
- `backbone plan --table` → bandit cells initialize
- `backbone run` with gate `noop`/`compile`/`pytest` passes; failures escalate to `escalation.expert`
- `data/doctor.json` marks each worker usable or skipped; router skips unusable workers
- Optional real NIM call per key: `make run worker=nim1 gate="noop"` through `make run worker=nim5 gate="noop"`
