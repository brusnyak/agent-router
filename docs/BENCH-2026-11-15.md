# Executor benchmark, 2026-11-15 (3 gated coding tasks per worker)
Tasks: `slugify`, `parse_duration`, `chunk` + tests, each gated by `pytest` on its test file, isolated worktree, one attempt allowed to repeat. Run: `scratchpad/bench/jobs.sh`, 4 in parallel, so wall time includes contention.

| worker | gate pass | wall s (t1,t2,t3) | notes |
|---|---|---|---|
| pi nim1 | 3/3 | 11, 18, 15 | free NIM key |
| pi nim2 | 3/3 | 13, 20, 13 | free NIM key |
| pi nim3 | 3/3 | 20, 19, 13 | free NIM key |
| claude | 3/3 | 18, 23, 24 | own subscription |
| jcode | 3/3 | 24, 30, 35 | ~29k input tokens per call (measured), parallel RAM claim not tested |
| codex | 3/3 | 57, 46, 64 | slowest |
| opencode | 0/3 first run; 1/1 after fix | 49, 113, 45; fixed run 35 | wrote into the MAIN repo instead of the isolated worktree (git worktree resolves to the main checkout); gate saw nothing. Fixed: workspace pinned in prompt plus a main-repo status guard |

Read: on small, well-specified tasks every worker passes; the free NIM keys are fastest and cost no subscription quota, so the bandit's job is to keep strong-but-scarce workers (claude, codex, agy) for large or review tasks where tier priors favour them, not to crown a winner here. Sample is 3 tasks of one class: it separates failure modes (opencode), not quality. Next benchmark needs harder tasks and a review class with an owner-labelled or cross-model check.
