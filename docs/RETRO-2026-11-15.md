# Retro: why the router took so long (evidence from this repo, 2026-11-15)

## What cost the time
1. **Wrong reading of "third party"** (biggest). Copies sat in `third_party/` as "study only, NOT built or run" (NOTICE.md, 2026-11-13). The owner wanted parts taken apart and used. Result: ports written from descriptions, and a hub built before the decision layer.
2. **Infrastructure before the thesis.** Fencing, leases, key pools, remote nodes shipped (commits 282af76, d459c67, b380815) while the enforcement experiment was still a plan (`docs/ENFORCEMENT-EXPERIMENT.md`, "nothing implemented"). Hook report: 76 prompts, 0 followed.
3. **Executors never smoke-tested together.** `runs` table: 24 of 101 blocked locally, 11 of 51 on Oracle: `codex` binary not found x11, no NIM keys in env x7, `pi` rc=127 on Oracle. The router could not even run itself without a shell wrapper until today.
4. **Drift between machines.** Oracle ran `dev/backbone` three commits behind with 48 dirty files; legacy FastAPI app (api/, graph/, ui/, bp/ clone: ~880 MB) stayed in the tree.
5. **Measurement without a metric the work moves.** Retrieval top-1 was 17.7% on the test split, below the always-guess floor (HANDOFF b.6); work continued on retrieval instead of on delegation outcome.

## What worked
- Gate-checked delegation: nim2 ported the rules engine (9 tests), codex ported the bandit (9 tests); both gates passed first attempt. Review still found one real flaw (hard cap froze learning), fixed.
- Comparing two rewrites of the same brief: codex gave 9 gated steps; the router's NIM rewrite had no gate and broke "push last".

## Do before the next project (30 min, not 3 days)
1. One discussion with a mid-tier model (sonnet/haiku/codex), output = ONE build prompt: goal, constraints, ordered steps each with a command gate, max 3 open questions. Save it in `docs/BUILD-PROMPT-*.md`.
2. Run `survey -> take apart -> copy -> port` (skill `harvest-then-improve`) before writing any module.
3. Smoke-test every executor with one real tiny task on day 1 (`backbone doctor` plus a gated run). A blocked executor is a day-1 ticket.
4. Define the one number the project moves (here: share of heavy tasks that go through the router; hook-follow rate) and print it daily.
5. One machine of truth: commit, then sync; never run uncommitted code on the hub.
