# Reasoned choice — isolated candidate

Candidate only: not registered, active, installed, or evidence of better behavior.
Use for a requested roast/comparison or a consequential choice with a falsifiable
advantage. Ordinary edits do not need this workflow. Existing permissions apply.

## Decision before defense

Name the user, decision, success threshold, and constraint that could reverse it.
Describe the ideal result for that user first; identify the measurable gap from
the proposal. Compare the actual current baseline, strongest feasible alternative,
and manual / do-nothing routes when plausible. Do not compare against a strawman
or assume an existing repository already meets the user's need.
Find the cheapest failure that defeats the intended benefit. Spend checking effort
on the claim that changes the choice, rather than equal criticism of every option.

## Reproduce the deciding claim

Use reproduce if available at `~/.agent-skills/core/reproduce/SKILL.md`; optional.
Keep CLAIM / DELTA / CHECK / RESULT / RECEIPT for each decisive claim; include
the exact command, exit code, and the output that decides it. If unavailable,
use that receipt format directly and label unchecked claims unknown; never vote proof.
Execution success is one claim. Fact correctness, useful artifact, independent
review, and authority to act are separate claims with separate evidence.

## Review without inheriting the defense

When independent review is warranted and authorized, use fresh contexts with the
exact artifact, raw evidence, decision, constraints, and acceptance threshold.
Withhold author rationale, desired verdict, and previous reviewers' conclusions.
Same weights in fresh contexts can expose anchoring; they are not independent
model families or proof. Reconcile disagreements against receipts, not consensus.
Escalate to a suitable available Claude/Codex reviewer only when an unresolved
material issue needs its capabilities. Name the issue and stopping check first;
reuse deterministic checks where decisive. No paid fallback or expanded authority.

## Would I use it?

Answer yes / no / conditional for the named user against the real baseline.
Name the winning evidence, remaining ideal-to-current gap, and the condition that
would reverse the choice. Prefer a reversible next experiment with an explicit
stop/rollback condition when the advantage remains unknown.
Before evaluating a skill change, freeze held-out cases, thresholds, baseline
version and candidate version. Run enclosed evaluation with permitted resources;
score actual outputs, failures and costs before seeing or tuning to held-out results.
Training examples are not held-out evidence. A structural test is not behavioral
proof; claim improvement only after a comparable baseline/candidate evaluation.
Promotion requires explicit authorized review of those receipts; never self-install
or globally register. Preserve the baseline and name the rollback target.

## Pressure case: continuous demand meets an exhausted budget

Owner wants 24/7 work; scheduler has used 26/26 calls and no active job.
Respect the cap. Show the blocking receipt, next eligible budget window, and a
bounded existing approved route only if its independent guards and scope permit.
Otherwise wait or request an explicit decision on scope; never reset counters,
raise caps, or create an alternate manifest solely to make the test run.
